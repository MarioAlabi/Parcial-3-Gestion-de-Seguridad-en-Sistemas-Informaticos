¿Qué es XSS?

Cross-Site Scripting es una vulnerabilidad que permite insertar código JavaScript en una página que otras personas visitan. El navegador no distingue: si el sitio le entrega código, lo ejecuta.

OWASP

Tipos de XSS

Elige un tipo, pulsa Empezar y avanza con Siguiente paso para ver cómo viaja el código malicioso.

n0cturno
Ana

Reflejado

Llega en un enlace trampa. Afecta a quien hace clic. Ej.: un buscador que repite lo buscado.

Almacenado

Se guarda en la base de datos y ataca a todos los visitantes. El más peligroso.

DOM

El JavaScript del propio sitio inserta el dato en la página, sin pasar por el servidor.

Prevención — Código lado a lado

Escribe una entrada y mira cómo la trata cada versión del código.

INSEGURO 
caja.innerHTML = comentario;
SEGURO 
caja.textContent = comentario;
✓ Se muestra como texto. Nada se ejecuta.

Lo que realmente se envía al HTML después de escapar:


      
Esas secuencias se llaman entidades. También existen numéricas: &#65; es la letra A. Te servirá en la Sala de Evidencias…

    


    
Las cinco capas de defensa (toca cada una)

    

      
1
Validar la entrada
Si un campo espera una edad, acepta solo números. Reduce riesgos, pero no reemplaza el escape.

      
2
Escapar la salida
Convierte < > & " ' en entidades. En PHP: htmlspecialchars($x, ENT_QUOTES, 'UTF-8').

      
3
Usar APIs seguras
textContent en vez de innerHTML. Cuidado con dangerouslySetInnerHTML (React) y v-html (Vue). Si necesitas HTML, sanitiza con DOMPurify.

      
4
Cookies HttpOnly
Set-Cookie: sesion=abc; HttpOnly; Secure; SameSite=Lax — JavaScript ya no puede leerla.

      
5
Content Security Policy
Content-Security-Policy: script-src 'self' — el navegador bloquea scripts inyectados en la página.
